# Правила code review

Правила ревью для людей и для Claude: локальный `/code-review` и workflow `claude-code-review.yml` в PR. Полные правила проекта лежат в `CLAUDE.md` (корень), `apps/api/CLAUDE.md` и `apps/web/CLAUDE.md`. Здесь собрано, что проверять в первую очередь и что не трогать.

## Как писать замечания

- На русском, по одному замечанию на проблему, со ссылкой `файл:строка`.
- Каждое замечание описывает конкретный сценарий: какие входные данные или какое состояние приводят к неверному результату. Без сценария это пожелание, а не дефект.
- Уровни:
  - **Критично** — уязвимость, утечка чужих данных, потеря данных, сломанный контракт api ↔ web, падение сборки или проверок `main`.
  - **Важно** — ошибка логики, нарушение архитектурных правил ниже, отсутствие тестов на новую логику.
  - **Мелочь** — читаемость, дублирование, необязательное упрощение. Мелочи помечать явно, они не блокируют слияние.
- Не повторять то, что ловят инструменты: Prettier, ESLint, `tsc`.

## Чеклист ревьюера

Пройти по порядку, подробности в разделах ниже. Пункт, который к PR не относится, пропускается.

**PR в целом**

- [ ] Заголовок и описание PR соответствуют диффу (`git diff main...HEAD`), изменений не по теме нет.
- [ ] В описании честно указано, какие проверки прошли и что не проверено вручную.
- [ ] Нет секретов, `.env`, `.claude/settings.local.json`, `.claude/memory/` и личных данных.

**Корректность и безопасность**

- [ ] Новые роуты api закрыты `AuthGuard`, данные ищутся по `id` + `userId`, ответы идут через мапперы.
- [ ] Входные данные проверяются схемой из shared: в api через `ZodValidationPipe`, в Server Action повторно.
- [ ] Суммы считаются через `Prisma.Decimal`, даты переводятся через маппер, граничные случаи (пустой список, страница за пределами, чужой `id`) обработаны.
- [ ] Ошибки api превращаются в правильные коды (400, 401, 404, 409), а в web доходят до пользователя (`FieldError`, `FormError`, toast).

**Архитектура**

- [ ] api: модули связаны только через `CommandBus`/`QueryBus`, к модели Prisma обращается только свой репозиторий.
- [ ] web: импорты соблюдают слои FSD, слайс доступен только через `index.ts`, в `app/` только реэкспорты.
- [ ] Контракт меняется только в `packages/shared`; ломающее изменение помечено, web обновлён в том же PR.

**Миграции и зависимости**

- [ ] Миграция есть, если менялась `schema.prisma`, и лежит в том же коммите; опасные операции обоснованы (см. ниже).
- [ ] `package-lock.json` меняется только вместе с `package.json`, зафиксированные версии не подняты.

**Тесты и документация**

- [ ] Новая логика покрыта тестами `*.spec.ts`, тесты проверяют поведение, а не реализацию.
- [ ] Изменённые правила отражены в `CLAUDE.md` пакета.

## Приоритеты

1. Безопасность и доступ к данным.
2. Корректность: суммы, даты, пагинация, граничные случаи.
3. Контракт `packages/shared` между api и web.
4. Архитектура: модули api и слои FSD в web.
5. Тесты и документация.

## Общее (монорепо)

- **Контракт.** Входные и выходные данные описаны Zod-схемами в `packages/shared`, типы выводятся через `z.infer`. Дублировать типы контракта в api или web нельзя. Ломающее изменение ответа api помечается в коммите `!` и `BREAKING CHANGE`, а web обновляется в том же PR.
- **Секреты.** `.env` и `.claude/settings.local.json` не коммитятся, в `.env.example` только заглушки. Токены, пароли, ключи и личные данные не попадают в код, логи и описание PR. Репозиторий публичный.
- **Версии.** TypeScript ~6.0, ESLint ^9 и Prisma ^7 зафиксированы. Подъём их на `@latest` — дефект.
- **Тесты** лежат рядом с кодом как `*.spec.ts` (Vitest). Новая логика в сервисах, хендлерах и чистых функциях из `lib` идёт вместе с тестами.
- **Документация.** Если PR меняет правило, описанное в `CLAUDE.md` пакета (новый эндпоинт, модуль, слайс, соглашение), этот `CLAUDE.md` правится в том же PR.
- **Git.**
  - Одна ветка — одна фича: изменения не по теме PR выносятся в отдельный PR.
  - Коммиты по Conventional Commits на русском.
  - Заголовок PR — обычная фраза без `type(scope):`.
  - Описание PR с разделами «Что сделано», «API», «Изменения в коде», «Проверка» соответствует диффу.

## Миграции и lock-файл

Это сгенерированные файлы: построчно их не читать и не комментировать стиль SQL или содержимое `package-lock.json`. Проверяются только признаки ниже.

**`apps/api/prisma/migrations/*`**

- Миграция появляется вместе с изменением `schema.prisma` и соответствует ему. Изменение схемы без миграции или миграция без изменения схемы — дефект.
- Уже влитые в `main` миграции не редактируются и не удаляются: Prisma хранит их контрольные суммы в базе, поэтому `migrate dev` у других разработчиков потребует сбросить базу, а на уже развёрнутых базах правка не применится. Исправление делается новой миграцией.
- Опасные операции требуют обоснования в описании PR:
  - `DROP TABLE`, `DROP COLUMN` и переименование, которое Prisma делает через удаление и создание, — теряют данные;
  - `NOT NULL` без `DEFAULT` на таблице с данными падает на непустой базе;
  - смена типа колонки и новый уникальный индекс могут упасть на существующих данных.
- `migration_lock.toml` не меняется (провайдер `postgresql`).

**`package-lock.json`**

- Меняется только вместе с `package.json` того же PR. Изменения lock-файла без причины — ошибка или ручная правка, такой PR не сливается.
- Все `resolved` указывают на `https://registry.npmjs.org`. Другой registry, `git+`- или `file:`-источник — критично: возможная атака на цепочку поставок.
- Зафиксированные версии (TypeScript, ESLint, Prisma) не поднялись транзитивно.

## API (`apps/api`)

**Безопасность и доступ**

- Все роуты закрыты глобальным `AuthGuard`. `@Public()` допустим только у health, register и login, любой новый `@Public()` требует обоснования.
- Данные пользователя ищутся по паре `id` + `userId` из `@CurrentUser()`, а не по `id` из запроса. Чужая запись даёт 404, а не 403, чтобы не раскрывать её существование.
- Наружу сущности отдаются через мапперы (`toPublicUser`, `toCategoryResponse`, маппер транзакций): никаких `passwordHash`, `userId` и сырых моделей Prisma в ответе.
- Входные данные проверяются `ZodValidationPipe` со схемой из shared. Тело, query и params без схемы — дефект. class-validator не используется.
- Переменные окружения читаются только через `ConfigService<Env, true>` и `get(key, { infer: true })`, новая переменная добавляется в схему `src/config/env.ts` и в `.env.example`.

**Архитектура модулей**

- Только репозиторий модуля обращается к своей модели Prisma (`prisma.user`, `prisma.category`, `prisma.transaction`).
- Модули связаны только через `CommandBus`/`QueryBus`: импорт чужого модуля или инжект его сервиса — дефект.
- Модуль `users` ничего не экспортирует. Новая связь auth → users оформляется как команда или запрос в `users/commands` или `users/queries`.
- Коды ошибок Prisma проверяются через `hasPrismaCode` из `src/common/prisma-errors.ts`. Ожидаемые ошибки превращаются в HTTP-коды проекта: P2025 → 404, конфликт уникальности → 409, удаление категории с транзакциями → 409.

**Данные**

- Суммы: строка в JSON, `Decimal(12, 2)` в БД, расчёты через `Prisma.Decimal`. Арифметика с `number` или `parseFloat` над деньгами — дефект.
- Даты транзакций: строка `YYYY-MM-DD`, перевод только через `toDbDate`/`fromDbDate`. `new Date(строка)` без маппера — дефект: возможен сдвиг на день из-за часового пояса.
- Список с пагинацией возвращает `{ items, total, page, pageSize }`, `pageSize` ограничен 100, сортировка стабильная (дата, затем id).
- Миграция Prisma идёт в одном коммите со схемой. Связь, которая ломает каскадное удаление пользователя (`Restrict`), — дефект.

**Код**

- ESM: относительные импорты с `.js`.
- Статические роуты (`summary`) объявлены раньше `:id`.
- Тесты без `Test.createTestingModule`: класс через `new`, зависимости — объекты с `vi.fn()` в `setup()`.

## Web (`apps/web`)

**Безопасность**

- JWT лежит только в httpOnly cookie `access_token`. Хранить токен в `localStorage`, в состоянии клиента или передавать его в клиентский компонент — дефект.
- Запросы к api идут только с сервера Next: `apiFetch` (`server-only`) и `authedFetch` для запросов от имени пользователя. `fetch` к api из клиентского компонента — дефект.
- Server Action повторно проверяет входные данные той же схемой (`toValidationError`), `id` проверяется через `validateId`, потому что попадает в путь запроса.
- Index слайса не реэкспортирует `server-only` код.
- Новая открытая страница добавляется в `PUBLIC_PATHS` осознанно. `dangerouslySetInnerHTML` без санитизации — дефект.

**Feature-Sliced Design**

- Слой импортирует только из слоёв ниже: `app` → `pages` → `widgets` → `features` → `entities` → `shared`. Слайсы одного слоя друг друга не импортируют.
- Слайс доступен снаружи только через `index.ts`, внутри слайса импорты относительные. Импорт из `shared` идёт по файлу, без `index.ts`.
- В `apps/web/app` только реэкспорты из `@/pages/*`: логика и разметка там — дефект.
- Код, нужный двум слайсам одного слоя, переезжает в слой ниже, а не импортируется сбоку.

**Next 16 и Base UI**

- Перед правками Next сверяться с `node_modules/next/dist/docs/`.
- `searchParams` и `params` — Promise.
- После мутации вызывается `refresh()` из `next/cache` (через `runMutation`), `redirect` пробрасывается через `unstable_rethrow`.
- В `error.tsx` проп `retry`, а не `reset`.
- Base UI: `render={<Link />}` вместо `asChild`, у кнопки-ссылки `nativeButton={false}`.
- Параметры URL проверяются и нормализуются редиректом. Значение из URL без проверки не уходит в запрос к api.

**Формы**

- `useForm<z.input<typeof schema>, unknown, z.output<typeof schema>>` + `zodResolver` со схемой из shared.
- Каждое поле обёрнуто в `Field` и показывает `FieldError`: ошибка поля из Server Action (`applyActionError`) должна быть видна.
- Форма в диалоге — отдельный внутренний компонент, чтобы открываться со свежими значениями.
- Русские тексты ошибок Zod задаются в `shared/config/zod.ts`, а не в схемах shared. Исключение — предметные проверки вроде `refine` согласия.

**UI**

- Компоненты shadcn в `shared/ui` руками не переписываются. Исключения задокументированы в `apps/web/CLAUDE.md` (`use-mobile.ts`, вариант `segmented` в `toggle.tsx`). Новое исключение тоже документируется там.
- Деньги и даты выводятся через `formatMoney`, `formatDate`, `formatMonth` из `shared/lib/format.ts`. Расчёты сумм на клиенте не делаются: суммы считает api.
- Доступность: интерактивные элементы — кнопки и ссылки, а не `div` с `onClick`; у групп и иконок есть `aria-label`; клавиатурная навигация не ломается.
- `setState` внутри `useEffect` запрещён правилом `react-hooks/set-state-in-effect`: использовать `useSyncExternalStore` или вычисление при рендере.

## Что не комментировать

- Форматирование, порядок импортов, кавычки: это задача Prettier и ESLint.
- Содержимое `prisma/migrations/*` и `package-lock.json` построчно: только проверки из раздела «Миграции и lock-файл».
- Сгенерированный код: `apps/api/src/generated/prisma`, неизменённые компоненты shadcn, `apps/web/AGENTS.md` (его переписывает `next dev`), `next-env.d.ts`.
- Файлы в `.claude/`: планы, промпты и шаблоны принадлежат автору проекта.
- Предложения поднять зафиксированные версии и заменить выбранный стек (Zod на class-validator и т. п.): эти решения приняты и записаны в `CLAUDE.md`.
- Вкусовые правки без сценария ошибки.
