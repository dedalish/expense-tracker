# Стендап

Собрать по **локальной** истории git, что сделано за период, и рассказать общую суть несколькими абзацами на русском. Skill только читает репозиторий: ничего не коммитить, не переключать ветки, не делать `fetch`/`pull`.

## 1. Период

Аргумент: `$ARGUMENTS`. Если пусто — `24 hours ago`. Иначе перевести в формат `--since` для git: «48 часов» → `48 hours ago`, «2 дня» → `2 days ago`, «неделя» → `1 week ago`, «вчера» → `yesterday`.

## 2. Сбор данных

Команды из корня репозитория, `<since>` — период из шага 1:

```bash
# Сегодняшняя дата для заголовка
date '+%d.%m.%Y'

# Все коммиты за период во всех локальных ветках: хеш, дата, автор, родители, ветка, заголовок
git log --all --since="<since>" --date=format:'%d.%m %H:%M' \
  --pretty=format:'%h%x09%ad%x09%an%x09%p%x09%S%x09%s'

# Ветки и их отставание/опережение от origin
git for-each-ref --format='%(refname:short)%09%(upstream:short)%09%(upstream:track)' refs/heads

# Текущая ветка и незакоммиченные изменения
git branch --show-current
git status --short
```

По необходимости:

- `git log --format='%h %s%n%b' <merge>^1..<merge>^2` — коммиты, вошедшие в PR, с телами: в теле коммита объяснено «зачем»;
- `git log main..<ветка> --format='%h %s%n%b'` — что в ветке ещё не влито в `main`;
- `git show --stat <hash>` или `git diff --stat` — если по заголовкам непонятно, что сделано, в том числе по незакоммиченным изменениям.

## 3. Разбор

- **Merge-коммиты** `Merge pull request #N from <owner>/<ветка>` — влитые PR, это главное «сделано».
- **Коммиты в `main` без PR** — тоже «сделано».
- **Коммиты, которых нет в `main`**, и незакоммиченные изменения — «в работе».
- Коммиты в Conventional Commits (`type(scope): описание`): по `type` и `scope` понять, что это — новая функциональность, исправление, документация, инфраструктура — и в каком пакете (`api`, `web`, `shared`, `db`).
- Связанные коммиты объединять в одну мысль: смысл важнее количества. Тела коммитов использовать, чтобы объяснить «зачем».

## 4. Формат ответа

Заголовок и **несколько абзацев связного текста**, без списков коммитов. Пересказывать суть, а не заголовки коммитов по одному.

```markdown
## Стендап · <дд.мм.гггг> · за <период>

<Абзац 1 — сделано. Что появилось или изменилось в проекте и зачем: влитые PR
с номерами, по пакетам и областям. 2–4 предложения.>

<Абзац 2 — в работе. Какие ветки ещё не влиты, запушены ли они, что лежит
незакоммиченным и к чему это относится. 1–3 предложения.>

<Абзац 3 — итог. Одно-два предложения: общий результат периода в цифрах
(коммиты, влитые PR, ветки в работе) и пометка, что данные локальные —
влитые на GitHub, но не подтянутые PR не видны.>
```

Правила:

- Абзацы, которым нечего сказать, не писать. Если за период коммитов нет, первым абзацем сказать это одной фразой.
- Хеши и номера PR упоминать в тексте, где они помогают найти изменение (`PR #13`, `1882597`), но не перечислять все.
- Автора упоминать, только если за период их больше одного. Email не показывать.
- Ничего не додумывать: планов на сегодня в git нет, о них не писать, если пользователь сам не попросил.
