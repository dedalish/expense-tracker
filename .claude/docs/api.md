# API

REST API на NestJS. Базовый URL: `http://localhost:3001/api`. Все тела запросов и ответов в JSON.

Интерактивная документация: Swagger UI на `/api/docs`, спецификация OpenAPI 3.0 на `/api/docs-json`. При `NODE_ENV=production` оба адреса отключены. Сейчас в Swagger подробно описаны только эндпоинты транзакций.

Все схемы из этого документа лежат в `packages/shared/src`.

## Общие правила

### Авторизация

- Все роуты, кроме `GET /health`, `POST /auth/register` и `POST /auth/login`, требуют заголовок:

  ```
  Authorization: Bearer <accessToken>
  ```

- `accessToken` возвращают регистрация и вход. Это JWT с алгоритмом HS256 и payload `{ sub: <id пользователя>, email }`. Срок жизни задаёт `JWT_EXPIRES_IN`, по умолчанию `1d`. Refresh-токена нет.
- Нет токена, токен невалиден или истёк — `401 { "message": "Unauthorized", "statusCode": 401 }`. Глобальный `AuthGuard` отвечает так раньше, чем запрос дойдёт до контроллера.
- **Изоляция данных.** Пользователь видит и меняет только свои категории и транзакции. Чужая запись выглядит как несуществующая: `404`.

### Форматы данных

| Тип              | Формат                                                                                                     |
| ---------------- | ---------------------------------------------------------------------------------------------------------- |
| id               | UUID (v7). Невалидный `:id` в пути даёт 400                                                                |
| Сумма `amount`   | В запросе число или строка: до 10 цифр, до 2 знаков после точки, больше 0. В ответе всегда строка `"1250.50"` |
| Дата `date`      | `YYYY-MM-DD`, без времени и часового пояса                                                                 |
| Дата-время       | ISO 8601 в UTC: `2026-10-22T06:13:17.000Z` (`createdAt`, `timestamp`)                                      |
| Тип транзакции   | `INCOME` (доход) или `EXPENSE` (расход)                                                                    |
| Цвет категории   | `#rrggbb`, приводится к нижнему регистру                                                                   |

Строки в теле запроса обрезаются по краям (trim). Email приводится к нижнему регистру.

### Ошибки

**400 — ошибка валидации** (`ZodValidationPipe`):

```json
{
  "message": "Validation failed",
  "errors": {
    "formErrors": [],
    "fieldErrors": {
      "amount": ["Сумма должна быть больше нуля"],
      "categoryId": ["Invalid UUID"]
    }
  }
}
```

- `formErrors` — ошибки всего объекта. Например, «Нужно передать хотя бы одно поле» в PATCH или невалидный `:id`.
- `fieldErrors` — ошибки по полям.

**Остальные ошибки** приходят в стандартном формате Nest:

```json
{ "message": "Транзакция не найдена", "error": "Not Found", "statusCode": 404 }
```

| Код | Когда                                                                                     |
| --- | ----------------------------------------------------------------------------------------- |
| 400 | данные не прошли схему; категория из тела транзакции не принадлежит пользователю           |
| 401 | нет или невалиден токен; неверный email или пароль; пользователь из токена удалён          |
| 404 | записи нет или она чужая                                                                   |
| 409 | email занят; название категории занято; удаление категории, у которой есть транзакции      |
| 500 | непредвиденная ошибка (например, гонка: категорию удалили во время создания транзакции)    |

## Health

### `GET /health`

Состояние API и базы. Авторизация не нужна.

**200:**

```json
{ "status": "ok", "database": "up", "timestamp": "2026-10-22T06:13:17.000Z" }
```

Если база недоступна, ответ всё равно 200, но с `"status": "degraded", "database": "down"`.

## Auth

### `POST /auth/register`

Регистрация. Авторизация не нужна.

| Поле                  | Тип     | Правила                                                            |
| --------------------- | ------- | ------------------------------------------------------------------ |
| `name`                | string  | 2–100 символов после trim                                          |
| `email`               | string  | валидный email, приводится к нижнему регистру                      |
| `password`            | string  | 8–128 символов                                                     |
| `personalDataConsent` | boolean | обязательно `true` (согласие на обработку ПДн по 152-ФЗ)           |

Время согласия сервер сохраняет в `users.personal_data_consent_at`.

**201:**

```json
{
  "accessToken": "eyJhbGciOiJIUzI1NiIs...",
  "user": {
    "id": "0199f0a2-...",
    "name": "Анна",
    "email": "anna@example.com",
    "createdAt": "2026-10-22T06:13:17.000Z"
  }
}
```

**Ошибки:** 400 — схема или согласие не дано; 409 — «Пользователь с таким email уже существует».

### `POST /auth/login`

Вход. Авторизация не нужна.

| Поле       | Тип    | Правила                |
| ---------- | ------ | ---------------------- |
| `email`    | string | валидный email         |
| `password` | string | 1–128 символов         |

**200:** тот же ответ, что у регистрации: `{ accessToken, user }`.

**Ошибки:** 400 — схема; 401 — «Неверный email или пароль». Ответ одинаковый для несуществующего email и неверного пароля, по тексту и по времени.

### `GET /auth/me`

Профиль текущего пользователя.

**200:** `{ id, name, email, createdAt }`.

**Ошибки:** 401 — нет токена или пользователь из токена уже удалён.

### `PATCH /auth/me`

Смена имени.

| Поле   | Тип    | Правила                    |
| ------ | ------ | -------------------------- |
| `name` | string | 2–100 символов после trim  |

**200:** обновлённый профиль `{ id, name, email, createdAt }`.

**Ошибки:** 400 — схема; 401 — нет токена или пользователь удалён.

## Categories

Категории принадлежат пользователю. Название уникально только в пределах одного пользователя.

Объект категории (`categorySchema`):

```json
{
  "id": "0199f0a2-...",
  "name": "Продукты",
  "color": "#22c55e",
  "icon": "🛒",
  "createdAt": "2026-10-22T06:13:17.000Z"
}
```

### `GET /categories`

Все категории пользователя, по названию по возрастанию.

**200:** `Category[]`.

### `POST /categories`

| Поле    | Тип    | Правила                                          |
| ------- | ------ | ------------------------------------------------ |
| `name`  | string | 1–50 символов после trim                         |
| `color` | string | `#rrggbb`, приводится к нижнему регистру         |
| `icon`  | string | emoji или имя иконки, 1–32 символа               |

**201:** `Category`.

**Ошибки:** 400 — схема; 401 — пользователь из токена удалён; 409 — «Категория с таким названием уже есть».

### `PATCH /categories/:id`

Частичное изменение: те же поля, что у `POST`, все необязательные, но нужно передать хотя бы одно.

**200:** `Category`.

**Ошибки:** 400 — схема или `:id` не UUID; 404 — «Категория не найдена»; 409 — название занято.

### `DELETE /categories/:id`

**204** без тела.

**Ошибки:** 400 — `:id` не UUID; 404 — «Категория не найдена»; 409 — «В категории есть транзакции». Сначала нужно удалить транзакции категории или перенести их в другую.

## Transactions

Объект транзакции (`transactionSchema`):

```json
{
  "id": "0199f0b1-...",
  "amount": "1250.50",
  "type": "EXPENSE",
  "description": "Продукты на неделю",
  "date": "2026-10-21",
  "categoryId": "0199f0a2-...",
  "createdAt": "2026-10-22T06:13:17.000Z"
}
```

`description` — строка или `null`.

### `POST /transactions`

| Поле          | Тип              | Правила                                                                    |
| ------------- | ---------------- | -------------------------------------------------------------------------- |
| `amount`      | number \| string | больше 0, до 10 цифр и до 2 знаков после точки: `1250.5`, `"1250.50"`      |
| `type`        | string           | `INCOME` или `EXPENSE`                                                     |
| `date`        | string           | `YYYY-MM-DD`                                                               |
| `categoryId`  | string           | UUID категории текущего пользователя                                       |
| `description` | string \| null   | необязательно, до 500 символов; пустая строка сохраняется как `null`       |

**201:** `Transaction`.

**Ошибки:** 400 — схема или «Категория не найдена» (категории нет или она чужая).

### `GET /transactions`

Постраничный список с фильтрами. Все параметры query необязательные.

| Параметр     | Тип         | По умолчанию | Описание                                        |
| ------------ | ----------- | ------------ | ----------------------------------------------- |
| `page`       | int ≥ 1     | `1`          | номер страницы                                  |
| `pageSize`   | int 1–100   | `10`         | размер страницы                                 |
| `type`       | enum        | —            | `INCOME` или `EXPENSE`                          |
| `categoryId` | UUID        | —            | только транзакции этой категории                |
| `dateFrom`   | YYYY-MM-DD  | —            | с этой даты включительно                        |
| `dateTo`     | YYYY-MM-DD  | —            | по эту дату включительно, не раньше `dateFrom`  |

Сортировка: по `date` по убыванию, внутри дня по `id` по убыванию. UUID v7 упорядочены по времени, поэтому новые записи идут первыми.

**200** (`transactionPageSchema`):

```json
{ "items": [/* Transaction */], "total": 42, "page": 1, "pageSize": 10 }
```

- `total` — число транзакций по фильтрам без учёта страниц.
- Если номер страницы больше числа страниц, ответ 200 с пустым `items`, а не ошибка.

**Ошибки:** 400 — параметры не прошли схему (например, `pageSize=500` или `dateFrom` позже `dateTo`).

### `GET /transactions/summary`

Сводка за календарный месяц по UTC.

| Параметр | Тип           | Обязателен |
| -------- | ------------- | ---------- |
| `month`  | int 1–12      | да         |
| `year`   | int 2000–2100 | да         |

**200** (`transactionSummarySchema`):

```json
{
  "month": 10,
  "year": 2026,
  "income": "85000.00",
  "expense": "31240.50",
  "balance": "53759.50",
  "byCategory": [
    {
      "categoryId": "0199f0a2-...",
      "name": "Продукты",
      "color": "#22c55e",
      "icon": "🛒",
      "type": "EXPENSE",
      "total": "12400.00",
      "count": 9
    }
  ]
}
```

- `balance` = `income − expense`, может быть отрицательным.
- `byCategory` — итоги по паре «категория + тип», от большей суммы к меньшей. Если в одной категории есть и доходы, и расходы, это две строки.
- Месяц без операций даёт нули и пустой `byCategory`.

**Ошибки:** 400 — `month` или `year` не прошли схему.

### `GET /transactions/:id`

**200:** `Transaction`. **Ошибки:** 400 — `:id` не UUID; 404 — «Транзакция не найдена».

### `PATCH /transactions/:id`

Частичное изменение: те же поля, что у `POST`, все необязательные, но нужно передать хотя бы одно. Новая `categoryId` должна принадлежать пользователю.

**200:** `Transaction`.

**Ошибки:** 400 — схема, `:id` не UUID или «Категория не найдена»; 404 — «Транзакция не найдена».

### `DELETE /transactions/:id`

**204** без тела. **Ошибки:** 400 — `:id` не UUID; 404 — «Транзакция не найдена».

## Пример сессии с curl

```bash
API=http://localhost:3001/api

# Регистрация (или вход через /auth/login) и сохранение токена
TOKEN=$(curl -s -X POST $API/auth/register -H 'Content-Type: application/json' \
  -d '{"name":"Анна","email":"anna@example.com","password":"secret123","personalDataConsent":true}' \
  | jq -r .accessToken)
AUTH="Authorization: Bearer $TOKEN"

# Категория
CAT=$(curl -s -X POST $API/categories -H "$AUTH" -H 'Content-Type: application/json' \
  -d '{"name":"Продукты","color":"#22C55E","icon":"🛒"}' | jq -r .id)

# Транзакция
curl -s -X POST $API/transactions -H "$AUTH" -H 'Content-Type: application/json' \
  -d "{\"amount\":\"1250.50\",\"type\":\"EXPENSE\",\"date\":\"2026-10-21\",\"categoryId\":\"$CAT\"}"

# Список расходов за октябрь и сводка
curl -s "$API/transactions?type=EXPENSE&dateFrom=2026-10-01&dateTo=2026-10-31" -H "$AUTH"
curl -s "$API/transactions/summary?month=10&year=2026" -H "$AUTH"
```
