# Схема базы данных

PostgreSQL 18 в Docker (`docker-compose.yml`), ORM — Prisma 7.

- Схема: `apps/api/prisma/schema.prisma`.
- Миграции: `apps/api/prisma/migrations/`.
- Клиент Prisma генерируется в `apps/api/src/generated/prisma`. Папка в `.gitignore`, клиент создаёт `prisma generate`.
- К базе обращается только `apps/api`. У каждой таблицы свой репозиторий: `UsersRepository`, `CategoriesRepository`, `TransactionsRepository`.

## Соглашения

- **Имена.** Таблицы и колонки в БД в `snake_case` во множественном числе (`users`, `category_id`). В коде модели и поля в `camelCase` (`User`, `categoryId`). Связь задаётся через `@map` и `@@map`.
- **Первичные ключи.** UUID v7 (`@default(uuid(7)) @db.Uuid`), генерирует Prisma. UUID v7 упорядочен по времени создания, поэтому вставки не фрагментируют индекс. Сортировка по `id` совпадает с порядком создания.
- **`created_at`.** Ставит БД (`DEFAULT CURRENT_TIMESTAMP`).
- **`updated_at`.** Обновляет Prisma (`@updatedAt`) при каждом `update`. Значения по умолчанию в БД нет.
- **Время.** Тип `TIMESTAMP(3)` без часового пояса. Prisma пишет и читает его как UTC.

## Таблица `users`

Учётные записи. Владелец — `UsersModule`. Другие модули получают пользователей только через команды и запросы CQRS.

| Колонка                    | Тип            | Null | Назначение                                                                                                                        |
| -------------------------- | -------------- | ---- | --------------------------------------------------------------------------------------------------------------------------------- |
| `id`                       | `UUID`         | нет  | Первичный ключ. Он же `sub` в JWT                                                                                                 |
| `name`                     | `TEXT`         | нет  | Отображаемое имя, 2–100 символов. Меняется через `PATCH /auth/me`                                                                 |
| `email`                    | `TEXT`         | нет  | Логин. Хранится в нижнем регистре (приводит схема в shared), поэтому уникальный индекс работает без учёта регистра               |
| `password_hash`            | `TEXT`         | нет  | Хэш argon2id в PHC-формате (алгоритм, параметры и соль в одной строке). Наружу никогда не отдаётся: `toPublicUser` его убирает    |
| `personal_data_consent_at` | `TIMESTAMP(3)` | да   | Когда пользователь дал согласие на обработку ПДн (152-ФЗ). Время ставит сервер при регистрации. `null` у тех, кто зарегистрировался до появления согласия |
| `created_at`               | `TIMESTAMP(3)` | нет  | Дата регистрации, отдаётся в `createdAt`                                                                                          |
| `updated_at`               | `TIMESTAMP(3)` | нет  | Время последнего изменения записи                                                                                                 |

**Индексы:** `users_pkey (id)`, `users_email_key UNIQUE (email)`. Повторный email даёт P2002, наружу 409.

## Таблица `categories`

Категории доходов и расходов. У каждого пользователя свой набор.

| Колонка      | Тип            | Null | Назначение                                                                                           |
| ------------ | -------------- | ---- | ---------------------------------------------------------------------------------------------------- |
| `id`         | `UUID`         | нет  | Первичный ключ                                                                                       |
| `user_id`    | `UUID`         | нет  | Владелец, FK → `users.id`. В ответы API не попадает                                                  |
| `name`       | `TEXT`         | нет  | Название, 1–50 символов. Уникально в пределах пользователя                                           |
| `color`      | `TEXT`         | нет  | Цвет в интерфейсе: hex `#rrggbb` в нижнем регистре                                                   |
| `icon`       | `TEXT`         | нет  | Emoji или имя иконки, 1–32 символа                                                                   |
| `created_at` | `TIMESTAMP(3)` | нет  | Когда создана                                                                                        |
| `updated_at` | `TIMESTAMP(3)` | нет  | Когда изменена                                                                                       |

**Индексы и ключи:**

- `categories_pkey (id)`.
- `categories_user_id_name_key UNIQUE (user_id, name)`. У разных пользователей названия могут совпадать. Дубликат у одного пользователя даёт P2002, наружу 409.
- `categories_user_id_fkey`: `user_id → users.id ON DELETE CASCADE`. Вместе с пользователем удаляются его категории.

## Таблица `transactions`

Доходы и расходы пользователя.

| Колонка       | Тип                | Null | Назначение                                                                                                                         |
| ------------- | ------------------ | ---- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `id`          | `UUID`             | нет  | Первичный ключ. Второй ключ сортировки списка после `date`                                                                          |
| `user_id`     | `UUID`             | нет  | Владелец, FK → `users.id`. Все запросы фильтруются по нему                                                                         |
| `category_id` | `UUID`             | нет  | Категория, FK → `categories.id`. Сервис проверяет, что категория принадлежит тому же пользователю                                  |
| `amount`      | `DECIMAL(12,2)`    | нет  | Сумма, **всегда больше 0**: до 10 цифр в целой части и 2 после точки. Знак не хранится, его задаёт `type`. В API передаётся строкой |
| `type`        | `transaction_type` | нет  | `INCOME` — доход, `EXPENSE` — расход                                                                                               |
| `description` | `TEXT`             | да   | Необязательный комментарий до 500 символов. Пустая строка сохраняется как `NULL`                                                   |
| `date`        | `DATE`             | нет  | День операции без времени. В API `YYYY-MM-DD`, в Prisma полночь UTC (`toDbDate`/`fromDbDate` в `transaction.mapper.ts`)            |
| `created_at`  | `TIMESTAMP(3)`     | нет  | Когда запись внесена в систему (не путать с `date`)                                                                                |
| `updated_at`  | `TIMESTAMP(3)`     | нет  | Когда изменена                                                                                                                     |

**Индексы и ключи:**

- `transactions_pkey (id)`.
- `transactions_user_id_date_idx (user_id, date)` — для списка с фильтром по датам и для сводки за месяц: `WHERE user_id = ? AND date >= ? AND date < ?`.
- `transactions_category_id_idx (category_id)` — для фильтра по категории и для проверки внешнего ключа при удалении категории.
- `transactions_user_id_fkey`: `user_id → users.id ON DELETE CASCADE`.
- `transactions_category_id_fkey`: `category_id → categories.id ON DELETE NO ACTION`.

### Почему `NO ACTION`, а не `RESTRICT`

Обе настройки запрещают удалить категорию, у которой есть транзакции. Попытка даёт P2003, наружу 409 «В категории есть транзакции». Различаются они моментом проверки:

- `RESTRICT` проверяется сразу на каждой строке. При удалении пользователя каскад может удалить категорию раньше транзакций, и удаление упадёт.
- `NO ACTION` проверяется в конце оператора, когда каскад уже удалил и транзакции. Поэтому удаление пользователя проходит целиком.

## Перечисление `transaction_type`

| Значение  | Смысл  |
| --------- | ------ |
| `INCOME`  | доход  |
| `EXPENSE` | расход |

В коде — `TransactionType` (Prisma), в shared — `transactionTypeSchema`.

## Удаление данных

| Что удаляется | Что происходит                                                              |
| ------------- | --------------------------------------------------------------------------- |
| пользователь  | каскадом удаляются его категории и транзакции                                |
| категория     | запрещено, если есть транзакции (409); иначе удаляется                       |
| транзакция    | удаляется одна запись                                                        |

## Как считается сводка за месяц

`TransactionsRepository.sumByCategory` делает `groupBy` по `(category_id, type)` с `SUM(amount)` и `COUNT(*)` за полуинтервал `[1-е число месяца, 1-е число следующего)`. Сервис:

- складывает доходы и расходы в `Prisma.Decimal`;
- подставляет название, цвет и иконку категории через `GetUserCategoriesQuery`;
- сортирует строки по сумме.

Правила:

- Миграция создаётся только вместе с изменением `schema.prisma`: `npm run db:migrate -- --name <имя>`.
- Влитые в `main` миграции не редактируются: их контрольные суммы хранятся в таблице `_prisma_migrations`.
- Готовые миграции применяются командой `npm run db:deploy -w @expense-tracker/api`.
- Просмотр данных: `npm run db:studio`.
